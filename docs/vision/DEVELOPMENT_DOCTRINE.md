# Development Doctrine

Authority: Kyle and Atlas, 13 November 2026.

**Define → Prototype → Demonstrate → Review → Refine → Approve → Expand → Verify.**

1. **Experience before expansion.** Build one coherent player experience before
   multiplying rooms, residents or activities. One convincing resident matters
   more than twenty unconvincing poses.
2. **Real gameplay evidence.** Inspect a running build, real simulation state and
   representative mobile viewports. Concept art, reports and isolated fixtures do
   not establish player-facing quality. A controlled game-time demonstration is
   permissible if occupancy, attendance and outcomes remain genuine.
3. **Creative checkpoints.** A: composition, scale, framing, atmosphere and UI.
   B: authored characters, real activities, props and occlusion. C: entry/exit,
   animation and interaction in motion. D: real saved colony, performance and
   regression integration. Stop expanding unapproved visual decisions. Continue
   unrelated safe engineering where useful.
4. **Preserve existing work.** Retain useful systems, history, assets, tests, saves
   and branches. Correct presentation failures without restarting the game.
5. **Small recoverable checkpoints.** Commit safe work frequently. Record exact
   branch, SHA, preview, unfinished changes and next acceptance target.
6. **Targeted verification.** Use relevant cheap/regression checks while actively
   building. Run broad suites at meaningful integration gates, rather than
   repeatedly spending the visual-review session on full endurance runs.
7. **Honest status.** Implemented means code exists. Functionally verified means
   behaviour was tested. Visually reviewed means actual gameplay was inspected.
   Creatively approved means Kyle and Atlas accepted the result. Never conflate
   these states or infer physical iPhone performance from desktop WebKit.
8. **Challenge weak approaches.** Explain save, performance or experience risks
   and offer an alternative that retains the creative intent. Do not silently
   replace an approved requirement with a convenient placeholder.

At each creative checkpoint deliver the exact commit, actual gameplay screenshot
or recording, brief changes, known defects, direct reference comparison and a
clear request for approval/correction. A long technical report is not evidence.
Obtain approval before spreading that presentation across the game.

During interruptions, preserve all safe work and a concise next-step handover.
Do not restart, abandon the overhaul, or prematurely discuss a final release.
